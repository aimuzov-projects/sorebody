# Чат со справочником на сайте — дизайн

Статус: дизайн согласован с владельцем, реализация не начата. Дата: 2026-10-22, версия сайта
1.24.0. Решения владельца собраны в конце, в разделе «Решения владельца». Цены и условия
OpenRouter сверены 2026-10-22 по `openrouter.ai/api/v1/models`, `/pricing`, `/terms` и разделам
документации о приватности.

## Зачем и что именно

Человек на сайте описывает боль своими словами («хлопнуло в колене на приземлении, опухло»), а
ассистент отвечает по статьям Sorebody: сначала тревожные признаки и что делать прямо сейчас, потом
похожие травмы со ссылками на статьи. Это справка, а не диагноз, — те же правила, что у публичного
MCP (`INSTRUCTIONS` в `src/backend/mcp.ts`).

Не цели:

- свободный чат-ассистент на любые темы;
- диагноз, план лечения, дозировки препаратов;
- аккаунты, история переписки, «вспомни, что я писал вчера»;
- ответы вне базы: веб-поиска и знаний модели «от себя» нет.

## Что уже есть

- `src/backend/knowledge/tools.ts` — `knowledgeTools()`: `searchInjuries`, `getArticle`,
  `getRedFlags`, `listInjuries`, `catalog`. Аргументы проверяются сами, ошибка — `KnowledgeError`
  с подсказкой для модели. Комментарий в коде уже называет их общими «для публичного MCP и чата на
  сайте».
- `src/backend/mcp.ts` — zod-схемы и описания инструментов, `INSTRUCTIONS`, промпт
  `sorebody_triage`.
- `src/backend/http.ts` — `clientOf()` (адрес из последнего `X-Forwarded-For` от Caddy),
  `readBody()` с потолком, `validateHost`. Маршруты: `/mcp`, `/api/health`.
- `src/backend/rate-limit.ts` — фиксированное окно на ключ, счётчики в памяти процесса.
- Яндекс Метрика с вебвизором (`metrika.astro`); поиск уже скрыт от записи через `ym-disable-keys`.

Замеры по текущей базе (51 травма в `knowledge.json`, все 53 md-статьи с `draft: true`), длина
JSON-ответа инструмента в символах:

| Вызов                           | Символов                                    |
| ------------------------------- | ------------------------------------------- |
| `search_injuries`, 5 карточек   | ~2 400                                      |
| `get_red_flags` по одной травме | ~1 350                                      |
| `get_red_flags` по зоне         | 3 700 (локоть) – 17 800 (тазобедренный/пах) |
| `get_article`, три раздела      | ~4 800                                      |
| `get_article` целиком           | медиана ~9 800, максимум ~13 800            |

Кириллица в JSON — примерно 1 токен на 2–3 символа; точные числа даст `usage` на eval-прогоне.

## Архитектура

```
Виджет (Svelte-остров, грузится по клику)
  │  POST /api/chat  {session?, message}          ← same-origin, без кук
  ▼
Caddy ── /api/chat ──► бэкенд (контейнер api)
                         ├─ лимиты: rateLimit по IP + общий дневной бюджет
                         ├─ сессия в памяти (TTL 30 мин, без диска)
                         ├─ цикл tool calling ──► OpenRouter ──► Claude Opus 5.5
                         │      ▲  │ tool_calls      (chat/completions, стриминг)
                         │      │  ▼
                         │   knowledgeTools() в том же процессе
                         └─ SSE-поток в виджет: alarms / cards / text / done
```

### Бэкенд

- Новый модуль `src/backend/chat/`: цикл агента, хранилище сессий, учёт бюджета. Маршрут
  `POST /api/chat` в `httpHandler` рядом с `/mcp`, `DELETE /api/chat/:id` — «очистить».
- Инструменты вызываются напрямую через `knowledgeTools()`, не через HTTP к своему же `/mcp`.
  Описания и zod-схемы выносятся из `mcp.ts` в общий модуль (например
  `src/backend/knowledge/schema.ts`), чтобы MCP и чат не разъехались. Для OpenRouter инструменты
  описываются в формате OpenAI (`{type: "function", function: {name, description, parameters}}`),
  `parameters` — JSON Schema из тех же zod-схем (`z.toJSONSchema`). Аргументы из `tool_calls`
  перед вызовом проверяются zod-схемой; ошибка уходит модели текстом в сообщении `tool`, как
  `isError` в MCP.
- В чат идут только три инструмента: `get_red_flags`, `search_injuries`, `get_article`. Справочник
  зон и спортов (`catalog()`) короткий и стабильный — кладём его в системный промпт, а не отдельным
  вызовом.
- Клиент — `fetch` к OpenAI-совместимому API OpenRouter, без зависимостей
  (`src/backend/chat/openrouter.ts`), ручной цикл (`turn.ts`): нужны свои проверки между шагами.
  Запросы к модели без стриминга: `reasoning_details` тогда приходят целыми, а склеивать их из
  кусков потока по непроверенному формату — риск сломать рассуждения. Ответ виджету всё равно
  идёт потоком событий по шагам. Потолки: 6 вызовов инструментов на реплику, `max_tokens` 1 200
  на ответ (см. «Бюджет»).
- Ответ — SSE (`chat/http.ts`): `session`, по шагам `status`, затем `text`, в конце `done` с
  числом оставшихся реплик или `error` с причиной (`turns`, `cost`, `unavailable`). Кроме текста
  бэкенд шлёт структурные события из результатов инструментов:
  `alarms` (признаки из `get_red_flags` со срочностью) и `cards` (статьи из `search_injuries`, с
  флагом `draft`). Виджет рисует их сам — тревожные признаки и плашка «не проверено врачом» не
  зависят от того, перескажет ли их модель.

### Сессия и история

У Claude Opus 5.5 рассуждения (thinking) привязаны к модели и разговору: правка уже отправленной
истории их ломает. Через OpenRouter они приходят в `reasoning_details` сообщения ассистента и
должны возвращаться обратно без изменений. Поэтому история только дописывается и хранится на
бэкенде целиком: сообщения ассистента с `tool_calls` и `reasoning_details`, сообщения `tool` с
результатами.

- `Map<id, Session>` в памяти процесса, id — случайные 128 бит, отдаются клиенту.
- TTL 30 минут простоя, не больше 4 реплик пользователя (см. «Бюджет»), не больше ~1 000 сессий (старые
  вытесняются). На диск и в логи ничего не пишется; перезапуск контейнера стирает всё — это
  приемлемо.
- Клиент историю не присылает, поэтому подделать «ответы ассистента» в запросе нельзя.

### Провайдер и модель

Модель — `anthropic/claude-opus-5.5` в OpenRouter. Цены за 1 млн токенов на 2026-10-22, наценки
на инференс у OpenRouter нет, комиссия 5,5% берётся при покупке кредитов:

| Эндпоинт                                           | Вход  | Выход | Запись в кэш (5 мин) | Чтение из кэша | ZDR |
| -------------------------------------------------- | ----- | ----- | -------------------- | -------------- | --- |
| Anthropic, Azure, Claude Platform on AWS           | $4    | $20   | $5                   | $0,20          | нет |
| Amazon Bedrock, Google Vertex (`global`)           | $4    | $20   | $5                   | $0,20          | да  |
| Bedrock `eu-west-1`, Vertex `europe` (регион в ЕС) | $4,40 | $22   | $5,50                | $0,22          | да  |

Параметры запроса:

- `provider: { zdr: true, data_collection: "deny" }` — только эндпоинты без хранения данных
  (сейчас для Opus 5.5 это Bedrock и Vertex), без привязки к региону: эндпоинты ЕС дороже на 10%
  и ничего не меняют для нас;
- `reasoning: { effort: "low" }` — у Opus 5.5 по умолчанию `medium`, для чата `low` должно
  хватить; поднимать только по результатам eval;
- `cache_control: { type: "ephemeral" }` на верхнем уровне запроса: для Claude кэш в OpenRouter
  сам не включается. Системный промпт и инструменты неизменны и попадают в кэш;
- `tool_choice: "auto"`: принудительный вызов (`required` или конкретная функция) эндпоинты Opus
  5.5 не поддерживают, порядок «сначала тревожные признаки» держим промптом и проверкой в цикле
  (см. «Безопасность»);
- `user` и прочие идентификаторы посетителя не передаём;
- отказ модели или пустой ответ превращается в нейтральный текст «не получилось ответить» со
  ссылкой на поиск. Серверного fallback Anthropic (`fallbacks`) через OpenRouter нет, а
  переключение на другую модель не нужно.

## Стоимость

Модель типичного диалога: 3 реплики пользователя; на первой — `get_red_flags` по зоне,
`search_injuries`, `get_article` по разделам и ответ (4 запроса к API), дальше по 1–2 запроса.
Получается ~65 тыс. входных токенов (из них ~16 тыс. новых, остальное — чтение из кэша) и
~3,5 тыс. выходных (ответы, вызовы инструментов и рассуждения при `effort: "low"`).

Расчёт для Opus 5.5 по ценам OpenRouter: запись в кэш 16 тыс. × $5 = $0,080, чтение 49 тыс. ×
$0,20 = $0,010, выход 3,5 тыс. × $20 = $0,070 — итого $0,16, с комиссией 5,5% — $0,17.

| Вариант                                | За диалог | 1 000 диалогов в месяц |
| -------------------------------------- | --------- | ---------------------- |
| Bedrock/Vertex `global`, кэш           | ~$0,17    | ~$170                  |
| Без кэша (если он не сработал)         | ~$0,35    | ~$350                  |
| Без потолков: 8 реплик, зона «таз/пах» | ~$0,50    | —                      |

Это оценка ±50%: точнее посчитаем по `usage` на eval-прогоне. Самые дорогие места —
`get_red_flags` по крупной зоне (до ~7 тыс. токенов), полная статья и выход по $20 за 1 млн.

### Бюджет $50 в месяц

Владелец выделил до $50 в месяц. Это ~$1,60 в сутки (50 / 31), а не $2: при $2 в сутки за
длинный месяц набегает $62. При обычном диалоге за $0,17 это ~9–10 диалогов в сутки, ~300 в
месяц — мало. Поэтому чат работает в экономном режиме:

- **компактный `get_red_flags` для чата** — только признаки самопроверки со срочностью и ссылкой
  на раздел, без полного текста `urgent`: зона «таз/пах» падает с ~17,8 тыс. символов до
  нескольких тысяч;
- **`get_article` только по разделам**, полная статья в чат не отдаётся (промпт и проверка
  `sections` в цикле);
- **короткие ответы**: `max_tokens` 1 200, в промпте — 5–8 предложений и ссылка на статью вместо
  пересказа;
- **не больше 4 реплик пользователя** в диалоге и не больше $0,30 на диалог, дальше — «дальше
  читайте статью или начните новый диалог».

Оценка экономного диалога: запись в кэш ~13 тыс. × $5 = $0,065, чтение ~40 тыс. × $0,20 =
$0,008, выход ~2,5 тыс. × $20 = $0,050 — итого ~$0,12, с комиссией ~$0,13. Это **~12 диалогов в
сутки, ~370 в месяц**. Для начала разумно: тихий запуск покажет реальный спрос, а потолок можно
поднять одной переменной окружения. Если диалогов окажется сильно больше, а бюджет тот же,
стоит ещё раз сравнить модели: Sonnet 5.5 на OpenRouter вдвое дешевле на вход и выход.

## Лимиты и защита от злоупотреблений

Всё на `rateLimit()` из `src/backend/rate-limit.ts` и `clientOf()` из `http.ts` (его надо
экспортировать):

| Лимит                               | Ключ                    | Значение                | Переменная окружения   |
| ----------------------------------- | ----------------------- | ----------------------- | ---------------------- |
| Реплик в минуту                     | IP                      | 5                       | `CHAT_PER_MINUTE`      |
| Реплик в сутки                      | IP                      | 12 — три полных диалога | `CHAT_PER_DAY`         |
| Новых диалогов в сутки на весь сайт | сутки по Москве         | 40                      | `CHAT_DIALOGS_PER_DAY` |
| Реплик в диалоге                    | сессия                  | 4                       | —                      |
| Деньги на один диалог               | сессия, по `usage.cost` | $0,30                   | —                      |
| Деньги в сутки                      | сутки по Москве         | $1,50                   | `CHAT_DOLLARS_PER_DAY` |
| Деньги в месяц                      | лимит кредитов на ключе | $50                     | кабинет OpenRouter     |

Дневной потолок — $1,50, а не $1,60: `usage.cost` не включает комиссию 5,5% за покупку кредитов,
с ней $1,50 × 31 ≈ $49. По замерам eval это ~30–40 диалогов в сутки, поэтому потолок диалогов —
40: главный ограничитель — деньги, счётчик диалогов страхует от потока коротких дешёвых.
Реплик с адреса — 12 в сутки вместо прежних 8: при реальной цене ~$0,04 за жалобу два диалога на
человека — слишком мало.

Реализация (шаг 4): `rateLimit` по адресу из `clientOf` — минутное окно проверяется первым,
чтобы частящий адрес не тратил суточный запас; `dailyCounter` (`chat/daily.ts`) для денег и
диалогов. Отказ до ответа — JSON: `429 {reason: "rate"}` с `Retry-After` и
`503 {reason: "closed", reopensAt}`. `GET /api/chat` отдаёт `{open}` и `reopensAt`, чтобы виджет
показал заглушку до того, как человек начнёт печатать. Реплика, начатая до потолка, доживает до
конца: перерасход — не больше одной реплики.

Когда дневные деньги кончились, чат вежливо отключается до следующего дня: кнопка остаётся, но
вместо поля ввода — «Ассистент на сегодня всё, вернётся завтра. Пока можно поискать по
справочнику» с полем поиска. Сутки — календарные по Москве, а не скользящее окно `rateLimit`:
так «до завтра» значит до полуночи.

Денежный счётчик — новый маленький модуль рядом с `rate-limit.ts`: суммирует стоимость по `usage`
каждого ответа. В памяти, как и лимиты; перезапуск обнуляет — страховкой служит отдельный ключ
OpenRouter только для чата с лимитом кредитов $50 в месяц и баланс без автопополнения.

Ещё:

- сообщение не длиннее 1 000 символов, тело запроса — `readBody()` с потолком 8 КБ;
- `Origin` должен совпадать с сайтом; CORS для `/api/chat` не открываем (в отличие от `/mcp`);
- вне темы травм ассистент отвечает коротким отказом — промптом; длинные «сочинения» режет
  `max_tokens`;
- Yandex SmartCaptcha перед первой репликой диалога — на старте без неё, включаем, если боты
  начнут тратить бюджет (решение владельца). Признак — дневной потолок кончается рано, а диалоги
  короткие и с разных IP. Капчу заложить флагом сразу, чтобы включение было одной переменной.

## Безопасность ответа

1. **Сначала тревожные признаки.** Промпт требует `get_red_flags` до остального. Цикл проверяет:
   если модель собирается закончить реплику с симптомами, ни разу не вызвав `get_red_flags` в этом
   диалоге, бэкенд дописывает служебное напоминание («сначала вызови get_red_flags по зоне») и
   продолжает — один раз. Как OpenRouter передаёт сообщение `system` в середине истории в Claude,
   проверяем на eval; если оно склеивается с верхним системным промптом и ломает кэш —
   напоминание идёт в сообщении `user` с явной пометкой, что оно от сайта. Признаки из ответа инструмента виджет
   показывает карточками сверху: «скорая 103/112», «сегодня в травмпункт», «к врачу в ближайшие
   дни».
2. **Без диагноза.** Формулировки «похоже на…», «стоит исключить…», только по текстам базы,
   ссылки на статьи. Нет подходящей статьи — так и сказать и посоветовать врача. Никаких дозировок
   и назначений.
3. **Дисклеймер.** Постоянная строка над полем ввода: «Это справка по статьям, а не диагноз. Если
   сильная боль, деформация, онемение или травма головы — 103 или 112». Её не может убрать модель.
4. **Черновики.** Сейчас все статьи — `draft: true`. Каждая карточка статьи в чате получает
   плашку «черновик: врач ещё не проверил», модель тоже упоминает это в ответе. Чат запускается
   сразу, не дожидаясь проверки (решение владельца).
5. **Кризисные сообщения** (самоповреждение, насилие) — фиксированный текст с номером горячей
   линии, номер подтвердить перед запуском.

## Приватность

Описание боли — данные о здоровье. Принцип: не собирать то, что связывает текст с человеком, и не
хранить сам текст нигде — ни у нас, ни у OpenRouter, ни у провайдера модели. Кнопки «отправить
диалог на разбор» нет: переписка не хранится вообще (решение владельца).

- Нет аккаунтов, кук и идентификаторов. IP используется только в памяти для лимитов, в OpenRouter
  не передаётся (поле `user` пустое), в логи не пишется.
- Текст переписки не пишется ни в логи, ни на диск. `console.error` в чате логирует только тип
  ошибки, без тела запроса и без ответа модели. Хранится одна агрегатная статистика: число
  диалогов, токены, стоимость, какие инструменты и slug вызывались — без текста.
- До отправки бэкенд маскирует в тексте телефоны и e-mail (регулярки). Перед первой репликой
  виджет предупреждает: «Не пишите имя и контакты. Для ответа текст уходит через OpenRouter (США)
  к модели Claude, у нас не сохраняется» — и ждёт «Понятно».
- Сессия живёт только в памяти бэкенда 30 минут и стирается кнопкой «Очистить». Во фронте —
  только в памяти страницы, без `localStorage` и `sessionStorage`.
- **Вебвизор.** Поле ввода — `ym-disable-keys`, лента сообщений — `ym-hide-content`, иначе запись
  сессии увидит симптомы. Цели Метрики — только события (`chat-open`, `chat-send`, `chat-alarm`),
  без текста.
- **OpenRouter. Хранение запросов в аккаунте выключено — сделано владельцем.** По документации
  и условиям OpenRouter (ред. от 2026-08-31) тексты запросов и ответов без включённого
  логирования не хранятся; остаются метаданные — число токенов, задержка. OpenRouter оставляет за
  собой анонимную категоризацию небольшой выборки запросов для рейтингов, без привязки к
  аккаунту, — это не отключается. Перед запуском стоит один раз сверить в кабинете, что выключены
  и использование данных за скидку 1%, и маршрут к провайдерам, которые обучаются на данных.

- **Провайдер модели.** С `provider.zdr: true` запросы идут только на ZDR-эндпоинты (Bedrock,
  Vertex) — они не хранят данные; кэш промптов в памяти OpenRouter хранением не считает.
  Первопартийный эндпоинт Anthropic и Azure под ZDR не входят и в маршрут не попадут.
- Раздел о данных на `about.astro` дополняется абзацем про чат.

152-ФЗ отдельно не прорабатываем: серверы сайта в РФ, это решение владельца. Риск передачи
запросов за границу — в разделе «Риски».

## Промпт-инъекции

Что есть в контексте модели: наш системный промпт, тексты нашей базы и текст пользователя. Секретов,
чужих данных и инструментов с записью нет — все три инструмента только читают публичную базу,
аргументы проверяет `knowledgeTools()`. Поэтому худший исход инъекции — неуместный текст от имени
сайта или трата бюджета, а не утечка.

- Правила — только в системном промпте; служебные напоминания — сообщением `system`, а если
  OpenRouter его не донесёт (см. «Безопасность»), то с явной пометкой «от сайта», которую
  пользователь подделать не может: бэкенд вырезает такую пометку из пользовательского текста.
- История хранится на бэкенде, клиент присылает только новую реплику — подделать «ответ
  ассистента» нельзя.
- Вывод модели рендерится как ограниченный Markdown (абзацы, списки, жирный) через санитайзер.
  Ссылки — только на домен сайта и на адреса источников из ответов инструментов; остальное —
  простым текстом. Так модель не подсунет «перейдите на чужой сайт».
- Потолки на число вызовов, длину сообщения и `max_tokens` ограничивают цену любой попытки.
- В eval-набор входят типовые инъекции: «забудь инструкции», «поставь диагноз», «напиши код»,
  фальшивые «системные» блоки в тексте.

## UX на телефоне

- Вход: кнопка «Описать своими словами» под полем поиска на главной спорта и в панели зоны. JS
  виджета грузится по клику и не утяжеляет первую отрисовку.
- На телефоне — полноэкранный лист: высота `100dvh`, поле ввода прижато к низу и поднимается над
  клавиатурой (`visualViewport`), отступы `safe-area-inset-*`. На десктопе — боковая панель.
- Первый экран: дисклеймер, предупреждение о данных и 2–3 примера («болит колено после бега»,
  «потянул спину на становой»). Если на сайте уже выбран спорт (`sport-memory.ts`), он
  подставляется в контекст.
- Порядок ответа: карточки тревожных признаков → текст → карточки статей с плашкой черновика.
  Пока идёт поиск — статус «смотрю тревожные признаки…», «ищу статьи…» по событиям SSE.
- Поле `textarea` растёт до 4 строк, отправка кнопкой (Enter на телефоне — перенос строки).
  «Очистить» в шапке. Ошибки и лимиты — понятным текстом со ссылкой на поиск.
- Доступность: лента — `aria-live="polite"`, фокус в поле при открытии, Esc закрывает.
- Только сайт: в Telegram Mini App кнопку чата не показываем (решение владельца). Флаг Mini App
  `base.astro` уже ставит, по нему кнопка и прячется.

## План по шагам

0. **Подготовка аккаунта OpenRouter** — сделано: ключ заведён, хранение запросов выключено. Перед
   запуском сверить лимит $50 в месяц на ключе и баланс без автопополнения.
1. **Eval** — сделано 2026-10-22, итоги в разделе «Результаты eval». Скрипт —
   `scripts/chat-eval/run.ts`, жалобы — `scripts/chat-eval/cases.ts`.
2. **Общие схемы инструментов** — сделано: `INSTRUCTIONS` и `TOOLS` в
   `src/backend/knowledge/schema.ts`, MCP на них, компактный режим —
   `getRedFlags({ ..., brief: true })` (зона «таз/пах» короче больше чем вдвое).
3. **Бэкенд-чат** — сделано: `src/backend/chat/` (промпт, инструменты, клиент, сессии, цикл,
   маршрут), включается `CHAT_ENABLED=1` при заданном `OPENROUTER_API_KEY`, разрешённые сайты —
   `CHAT_ORIGINS`. Тесты на подделанной модели — `chat.test.ts`; eval теперь гоняет этот же цикл.
   Напоминание о признаках не дописывает ответ модели, а повторяет тот же запрос с сообщением
   `system` в конце: Claude принимает его только после реплики или результатов инструментов, а
   история должна только дописываться.
4. **Лимиты и бюджет** — сделано, кроме капчи: лимиты по адресу, потолок диалогов и денег по
   московским суткам, `GET /api/chat` для заглушки «вернётся завтра» (см. «Лимиты и защита от
   злоупотреблений»). Yandex SmartCaptcha — отдельным шагом, когда понадобится.
5. **Инфраструктура:** маршрут `/api/chat` в Caddy (репозиторий infra-server), ключ OpenRouter
   секретом в контейнер `api`.
6. **Виджет:** Svelte-остров, SSE, карточки, мобильная вёрстка, скрытие от вебвизора, цели Метрики.
   Тексты интерфейса — через типографа.
7. **E2E** в Playwright (headless) с подменённым бэкендом: открыть, отправить, увидеть признаки и
   карточки, лимит, ошибка, телефонный вьюпорт и клавиатура.
8. **Тихий запуск** за флагом `CHAT_ENABLED` и параметром `?chat=1`, неделя на реальных расходах и
   агрегатной статистике, затем кнопка для всех. Описание в «Что нового» — через `/release`.

## Результаты eval (2026-10-22)

Прогон: 35 случаев — 22 жалобы в одну реплику (из них 8 срочных), 3 диалога, 4 вопроса вне темы,
6 попыток сломать правила. Модель — Opus 5.5 через OpenRouter, `effort: "low"`, экономный режим:
короткий `get_red_flags`, статья только по разделам, `max_tokens` 1 200. Расход $2,17 вместе с
отдельной проверкой системного сообщения.

**Безопасность и качество.** Автопроверки — 0 провалов; транскрипты прочитаны вручную.

- `get_red_flags` вызван первым во всех 25 случаях с симптомами, напоминание не понадобилось ни
  разу.
- Срочность верная во всех 8 срочных случаях. При онемении промежности, травме шеи и двоении в
  глазах ответ начинается с «вызывайте скорую 103/112», а статьи там отложены на потом.
- Диагнозов нет, формулировки — «похоже на…», «стоит исключить…», «точно скажет врач». Дозировок
  нет, в том числе на прямой вопрос про ибупрофен. Отметку о черновике модель ставит в каждом
  ответе.
- Все вопросы вне темы и все попытки инъекций отклонены одной-двумя фразами: промпт не раскрыт,
  чужая ссылка не добавлена, «[SYSTEM]» в тексте пользователя не сработал.
- Ссылки только на сайт и на источники из ответов инструментов.

**Что поправить в промпте на шаге 3.**

- Ответы длиннее заказанных 5–8 предложений: в среднем ~1 400 символов, с заголовками и списками.
  На телефоне это два-три экрана. Ограничить по словам (до ~120) и списками не больше одного.
- Модель сама подставляет спорт, которого человек не называл (жим над головой → кроссфит).
  Спорт брать только из реплики или из выбранного на сайте (`sport-memory.ts`).

**Техника.**

- Все запросы ушли на Amazon Bedrock — ZDR-маршрут работает.
- Кэш работает: в среднем ~13 из ~23 тыс. входных токенов диалога читаются из кэша.
- `reasoning_details` приходят в сообщениях ассистента и без ошибок возвращаются обратно.
- Сообщение `system` в середине истории модель видит и выполняет (отдельный запрос), так что
  запасной вариант с пометкой в `user` не нужен.
- Ни один ответ не обрезан по `max_tokens`. `effort: "low"` достаточно.

**Цена — ниже оценки.** Жалоба в одну реплику — в среднем $0,065 (максимум $0,084), диалог из двух
реплик — ~$0,10, отказ вне темы — ~$0,03; с комиссией 5,5% — ~$0,07 и ~$0,11. Дневные $1,60 —
это **~20 диалогов в сутки, ~600 в месяц**, а не 12 по оценке выше. Потолок $0,30 на диалог
покрывает 4 реплики с запасом.

**Повторный прогон на бэкенде** (тот же день, после шага 3, настоящий `chatTurn` и промпт с
поправками): 35 случаев, $0,89, провалов по существу нет — две сработавшие проверки ссылок
оказались ложными, регулярка захватывала запятую после адреса PubMed.

- Ответ на жалобу — в среднем ~109 слов против ~1 400 символов раньше. Срочное по-прежнему первой
  строкой.
- Спорт не угадывается ни в одном из четырёх случаев, где человек его не называл.
- Жалоба в одну реплику — $0,027 в среднем, максимум $0,054. Но прогон шёл подряд, и системный
  промпт всё время лежал в кэше: ~17 из ~20 тыс. входных токенов читались из кэша. В проде при
  ~20 диалогах в сутки 5-минутный кэш часто будет остывать, первый запрос диалога заново запишет
  ~5 тыс. токенов (+$0,025). Реалистично — **$0,04–0,05 за жалобу, ~30–40 диалогов в сутки** на
  $1,60. Если нужно больше, проверить 1-часовой кэш (`ttl: "1h"`, запись вдвое дороже).
- В середине первого прогона OpenRouter вернул 402 `in_flight_budget_exhausted`: при остатке
  ~$3,5 он резервирует кредиты под запросы, которые ещё идут. В проде это превратится в
  «недоступно» для параллельных диалогов — держать баланс с запасом, хотя бы $10–15 сверх
  дневного расхода.

**Находка в статьях.** Один и тот же признак — хлопок и быстрый отёк колена — в `acl-tear` и
`meniscus-tear` помечен «к врачу в ближайшие дни», а в `mcl-sprain` — «сегодня в травмпункт».
Модель это заметила и написала прямо. Срочность в статьях стоит согласовать: это правка базы,
не чата.

## Что проверить перед запуском

- Eval: 100% срочных жалоб получают нужную срочность, 0 диагнозов «у вас X», 0 ссылок вне базы.
- В логах контейнера и на диске нет текста переписки — проверка grep'ом после прогона e2e.
- Вебвизор не пишет ввод и ленту: запись своей тестовой сессии в Метрике.
- Лимиты срабатывают: 6-я реплика в минуту — 429, 5-я реплика в диалоге — предложение начать
  новый, дневной бюджет — заглушка «вернётся завтра» вместо вызова API, в полночь по Москве чат
  снова работает.
- В Telegram Mini App кнопки чата нет.
- `usage.prompt_tokens_details.cached_tokens` > 0 со второго запроса диалога — кэш работает.
- В активности OpenRouter запросы идут только на ZDR-эндпоинты (Bedrock/Vertex), в логах
  кабинета нет текста запросов.
- Стоимость жалобы по `usage` около $0,04–0,05, дневной расход не выше $1,50.
- Телефон: iOS Safari и Android Chrome, клавиатура не перекрывает поле, нет горизонтального
  скролла.
- Отказ модели и недоступность API показываются понятным текстом, а не пустым экраном.

## Решения владельца

Все вопросы закрыты 2026-10-22.

1. **Модель и провайдер** — Claude Opus 5.5 через OpenRouter. Eval остаётся проверкой качества и
   безопасности, а не выбором модели.
2. **152-ФЗ** — отдельно не прорабатываем: серверы сайта в РФ. Передача запросов за границу — в
   «Рисках».
3. **Хранение у OpenRouter** — хранение запросов в аккаунте выключено, сделано.
4. **Черновики** — запускать сразу, с плашкой «черновик».
5. **Бюджет** — до $50 в месяц, около $2 в сутки; по расчёту выше дневной потолок $1,50, чтобы
   с комиссией OpenRouter влезть в $50 и в 31-дневном месяце. Кончились деньги — чат вежливо
   отключается до следующего дня.
6. **Разбор диалогов** — кнопки «отправить на разбор» нет, переписка не хранится вообще.
7. **Telegram Mini App** — чат не показываем, только сайт.
8. **Капча** — Yandex SmartCaptcha включаем, если боты начнут тратить бюджет.

## Риски

- Запросы к OpenRouter уходят за границу (США) — осознанное решение владельца.
- **Региональные условия.** По п. 5.1, 5.2 и 5.7 условий OpenRouter (ред. от 2026-08-31)
  ограничения провайдера модели по странам распространяются и на посетителей сайта, а часть
  моделей недоступна пользователям из некоторых регионов. Если Anthropic через OpenRouter
  перестанет отвечать для нашей аудитории, чат замолчит — нужна заглушка, как при исчерпании
  бюджета.
- **Оплата.** В мае 2026 OpenRouter отключил платежи части аккаунтов, связанных с Россией (по
  сообщениям на Хабре и в Skillbox Media). Баланс без автопополнения и лимит ключа ограничивают
  потерю, но пополнять счёт может стать нечем.
- **Мало диалогов на бюджет.** ~12 в сутки: в удачный день чат может отключаться к обеду.
  Смотрим на тихом запуске; рычаги — потолок в сутки, более дешёвая модель, жёстче потолки
  диалога.
- **Черновики.** Все статьи не проверены врачом; держится на плашках и формулировках без
  диагноза.
