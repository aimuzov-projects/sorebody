# Чат со справочником на сайте — дизайн

Статус: черновик для решения владельца, без реализации. Дата: 2026-10-22, версия сайта 1.24.0.

Решение владельца: провайдер — OpenRouter, модель — Claude Opus 5.5 через него. Цены и условия
OpenRouter сверены 2026-10-22 по `openrouter.ai/api/v1/models`, `/pricing`, `/terms` и разделам
документации о приватности.

## Зачем и что именно

Человек на сайте описывает боль своими словами («хлопнуло в колене на приземлении, опухло»), а
ассистент отвечает по статьям Sorebody: сначала тревожные признаки и что делать прямо сейчас, потом
похожие травмы со ссылками на статьи. Это справка, а не диагноз, — те же правила, что у публичного
MCP (`INSTRUCTIONS` в `src/backend/mcp.ts`).

Не цели:

- свободный чат-ассистент на любые темы;
- диагноз, план лечения, дозировки препаратов;
- аккаунты, история переписки, «вспомни, что я писал вчера»;
- ответы вне базы: веб-поиска и знаний модели «от себя» нет.

## Что уже есть

- `src/backend/knowledge/tools.ts` — `knowledgeTools()`: `searchInjuries`, `getArticle`,
  `getRedFlags`, `listInjuries`, `catalog`. Аргументы проверяются сами, ошибка — `KnowledgeError`
  с подсказкой для модели. Комментарий в коде уже называет их общими «для публичного MCP и чата на
  сайте».
- `src/backend/mcp.ts` — zod-схемы и описания инструментов, `INSTRUCTIONS`, промпт
  `sorebody_triage`.
- `src/backend/http.ts` — `clientOf()` (адрес из последнего `X-Forwarded-For` от Caddy),
  `readBody()` с потолком, `validateHost`. Маршруты: `/mcp`, `/api/health`.
- `src/backend/rate-limit.ts` — фиксированное окно на ключ, счётчики в памяти процесса.
- Яндекс Метрика с вебвизором (`metrika.astro`); поиск уже скрыт от записи через `ym-disable-keys`.

Замеры по текущей базе (51 травма в `knowledge.json`, все 53 md-статьи с `draft: true`), длина
JSON-ответа инструмента в символах:

| Вызов                           | Символов                                    |
| ------------------------------- | ------------------------------------------- |
| `search_injuries`, 5 карточек   | ~2 400                                      |
| `get_red_flags` по одной травме | ~1 350                                      |
| `get_red_flags` по зоне         | 3 700 (локоть) – 17 800 (тазобедренный/пах) |
| `get_article`, три раздела      | ~4 800                                      |
| `get_article` целиком           | медиана ~9 800, максимум ~13 800            |

Кириллица в JSON — примерно 1 токен на 2–3 символа; точные числа даст `usage` на eval-прогоне.

## Архитектура

```
Виджет (Svelte-остров, грузится по клику)
  │  POST /api/chat  {session?, message}          ← same-origin, без кук
  ▼
Caddy ── /api/chat ──► бэкенд (контейнер api)
                         ├─ лимиты: rateLimit по IP + общий дневной бюджет
                         ├─ сессия в памяти (TTL 30 мин, без диска)
                         ├─ цикл tool calling ──► OpenRouter ──► Claude Opus 5.5
                         │      ▲  │ tool_calls      (chat/completions, стриминг)
                         │      │  ▼
                         │   knowledgeTools() в том же процессе
                         └─ SSE-поток в виджет: alarms / cards / text / done
```

### Бэкенд

- Новый модуль `src/backend/chat/`: цикл агента, хранилище сессий, учёт бюджета. Маршрут
  `POST /api/chat` в `httpHandler` рядом с `/mcp`, `DELETE /api/chat/:id` — «очистить».
- Инструменты вызываются напрямую через `knowledgeTools()`, не через HTTP к своему же `/mcp`.
  Описания и zod-схемы выносятся из `mcp.ts` в общий модуль (например
  `src/backend/knowledge/schema.ts`), чтобы MCP и чат не разъехались. Для OpenRouter инструменты
  описываются в формате OpenAI (`{type: "function", function: {name, description, parameters}}`),
  `parameters` — JSON Schema из тех же zod-схем (`z.toJSONSchema`). Аргументы из `tool_calls`
  перед вызовом проверяются zod-схемой; ошибка уходит модели текстом в сообщении `tool`, как
  `isError` в MCP.
- В чат идут только три инструмента: `get_red_flags`, `search_injuries`, `get_article`. Справочник
  зон и спортов (`catalog()`) короткий и стабильный — кладём его в системный промпт, а не отдельным
  вызовом.
- Клиент — пакет `openai` с `baseURL: "https://openrouter.ai/api/v1"` (OpenAI-совместимый API
  OpenRouter), стриминг, ручной цикл: нужны свои проверки между шагами. Потолки: 6 вызовов
  инструментов на реплику, `max_tokens` ~2 000 на ответ.
- Ответ — SSE. Кроме текста бэкенд шлёт структурные события из результатов инструментов:
  `alarms` (признаки из `get_red_flags` со срочностью) и `cards` (статьи из `search_injuries`, с
  флагом `draft`). Виджет рисует их сам — тревожные признаки и плашка «не проверено врачом» не
  зависят от того, перескажет ли их модель.

### Сессия и история

У Claude Opus 5.5 рассуждения (thinking) привязаны к модели и разговору: правка уже отправленной
истории их ломает. Через OpenRouter они приходят в `reasoning_details` сообщения ассистента и
должны возвращаться обратно без изменений. Поэтому история только дописывается и хранится на
бэкенде целиком: сообщения ассистента с `tool_calls` и `reasoning_details`, сообщения `tool` с
результатами.

- `Map<id, Session>` в памяти процесса, id — случайные 128 бит, отдаются клиенту.
- TTL 30 минут простоя, не больше 8 реплик пользователя, не больше ~1 000 сессий (старые
  вытесняются). На диск и в логи ничего не пишется; перезапуск контейнера стирает всё — это
  приемлемо.
- Клиент историю не присылает, поэтому подделать «ответы ассистента» в запросе нельзя.

### Провайдер и модель

Модель — `anthropic/claude-opus-5.5` в OpenRouter. Цены за 1 млн токенов на 2026-10-22, наценки
на инференс у OpenRouter нет, комиссия 5,5% берётся при покупке кредитов:

| Эндпоинт                                           | Вход  | Выход | Запись в кэш (5 мин) | Чтение из кэша | ZDR |
| -------------------------------------------------- | ----- | ----- | -------------------- | -------------- | --- |
| Anthropic, Azure, Claude Platform on AWS           | $4    | $20   | $5                   | $0,20          | нет |
| Amazon Bedrock, Google Vertex (`global`)           | $4    | $20   | $5                   | $0,20          | да  |
| Bedrock `eu-west-1`, Vertex `europe` (регион в ЕС) | $4,40 | $22   | $5,50                | $0,22          | да  |

Параметры запроса:

- `provider: { zdr: true, data_collection: "deny" }` — только эндпоинты без хранения данных
  (сейчас для Opus 5.5 это Bedrock и Vertex); `only` с конкретными эндпоинтами — если юрист
  попросит держать обработку в ЕС (`amazon-bedrock/eu-west-1`, `google-vertex/europe`, +10% к
  цене);
- `reasoning: { effort: "low" }` — у Opus 5.5 по умолчанию `medium`, для чата `low` должно
  хватить; поднимать только по результатам eval;
- `cache_control: { type: "ephemeral" }` на верхнем уровне запроса: для Claude кэш в OpenRouter
  сам не включается. Системный промпт и инструменты неизменны и попадают в кэш;
- `tool_choice: "auto"`: принудительный вызов (`required` или конкретная функция) эндпоинты Opus
  5.5 не поддерживают, порядок «сначала тревожные признаки» держим промптом и проверкой в цикле
  (см. «Безопасность»);
- `user` и прочие идентификаторы посетителя не передаём;
- отказ модели или пустой ответ превращается в нейтральный текст «не получилось ответить» со
  ссылкой на поиск. Серверного fallback Anthropic (`fallbacks`) через OpenRouter нет, а
  переключение на другую модель не нужно.

## Стоимость

Модель типичного диалога: 3 реплики пользователя; на первой — `get_red_flags` по зоне,
`search_injuries`, `get_article` по разделам и ответ (4 запроса к API), дальше по 1–2 запроса.
Получается ~65 тыс. входных токенов (из них ~16 тыс. новых, остальное — чтение из кэша) и
~3,5 тыс. выходных (ответы, вызовы инструментов и рассуждения при `effort: "low"`).

Расчёт для Opus 5.5 по ценам OpenRouter: запись в кэш 16 тыс. × $5 = $0,080, чтение 49 тыс. ×
$0,20 = $0,010, выход 3,5 тыс. × $20 = $0,070 — итого $0,16, с комиссией 5,5% — $0,17.

| Вариант                                  | За диалог | 1 000 диалогов в месяц |
| ---------------------------------------- | --------- | ---------------------- |
| Bedrock/Vertex `global`, кэш             | ~$0,17    | ~$170                  |
| Регион ЕС (+10%), кэш                    | ~$0,19    | ~$190                  |
| Без кэша (если он не сработал)           | ~$0,35    | ~$350                  |
| Тяжёлый диалог: 8 реплик, зона «таз/пах» | ~$0,50    | —                      |

Это оценка ±50%: точнее посчитаем по `usage` на eval-прогоне. Самые дорогие места —
`get_red_flags` по крупной зоне (до ~7 тыс. токенов) и полная статья. Если упрёмся в цену —
компактный режим `get_red_flags` для чата: только признаки без полного текста раздела `urgent`.

## Лимиты и защита от злоупотреблений

Всё на `rateLimit()` из `src/backend/rate-limit.ts` и `clientOf()` из `http.ts` (его надо
экспортировать):

| Лимит                               | Ключ                      | Значение для старта                                     |
| ----------------------------------- | ------------------------- | ------------------------------------------------------- |
| Реплик в минуту                     | IP                        | 5                                                       |
| Реплик в сутки                      | IP                        | 30 (`windowMs: 86_400_000`)                             |
| Новых диалогов в сутки на весь сайт | `'*'`                     | 60                                                      |
| Деньги на один диалог               | счётчик сессии по `usage` | $0,60 — дальше «начните новый диалог»                   |
| Деньги в сутки                      | общий счётчик по `usage`  | $10 — дальше чат отвечает «на сегодня лимит, вот поиск» |

$10 в сутки — это ~55–60 обычных диалогов и не больше ~$300 в месяц. Цифры стартовые, их
утверждает владелец (открытый вопрос о бюджете).

Денежный счётчик — новый маленький модуль рядом с `rate-limit.ts`: суммирует стоимость по `usage`
каждого ответа, окно — сутки. В памяти, как и лимиты; перезапуск обнуляет — страховкой служит
отдельный ключ OpenRouter только для чата с лимитом кредитов на ключе и небольшой баланс без
автопополнения.

Ещё:

- сообщение не длиннее 1 000 символов, тело запроса — `readBody()` с потолком 8 КБ;
- `Origin` должен совпадать с сайтом; CORS для `/api/chat` не открываем (в отличие от `/mcp`);
- вне темы травм ассистент отвечает коротким отказом — промптом; длинные «сочинения» режет
  `max_tokens`;
- если боты пробьют лимиты по IP — включаем Yandex SmartCaptcha перед первой репликой диалога.
  На старте без неё.

## Безопасность ответа

1. **Сначала тревожные признаки.** Промпт требует `get_red_flags` до остального. Цикл проверяет:
   если модель собирается закончить реплику с симптомами, ни разу не вызвав `get_red_flags` в этом
   диалоге, бэкенд дописывает служебное напоминание («сначала вызови get_red_flags по зоне») и
   продолжает — один раз. Как OpenRouter передаёт сообщение `system` в середине истории в Claude,
   проверяем на eval; если оно склеивается с верхним системным промптом и ломает кэш —
   напоминание идёт в сообщении `user` с явной пометкой, что оно от сайта. Признаки из ответа инструмента виджет
   показывает карточками сверху: «скорая 103/112», «сегодня в травмпункт», «к врачу в ближайшие
   дни».
2. **Без диагноза.** Формулировки «похоже на…», «стоит исключить…», только по текстам базы,
   ссылки на статьи. Нет подходящей статьи — так и сказать и посоветовать врача. Никаких дозировок
   и назначений.
3. **Дисклеймер.** Постоянная строка над полем ввода: «Это справка по статьям, а не диагноз. Если
   сильная боль, деформация, онемение или травма головы — 103 или 112». Её не может убрать модель.
4. **Черновики.** Сейчас все статьи — `draft: true`. Каждая карточка статьи в чате получает
   плашку «врач ещё не проверил», модель тоже упоминает это в ответе. Запускать ли чат до проверки
   хотя бы частых статей — открытый вопрос.
5. **Кризисные сообщения** (самоповреждение, насилие) — фиксированный текст с номером горячей
   линии, номер подтвердить перед запуском.

## Приватность и 152-ФЗ

Описание боли — данные о здоровье, по 152-ФЗ это специальная категория (ст. 10). Принцип: не
собирать то, что связывает текст с человеком, и не хранить сам текст.

- Нет аккаунтов, кук и идентификаторов. IP используется только в памяти для лимитов, в OpenRouter
  не передаётся (поле `user` пустое), в логи не пишется.
- Текст переписки не пишется ни в логи, ни на диск. `console.error` в чате логирует только тип
  ошибки, без тела запроса и без ответа модели. Хранится одна агрегатная статистика: число
  диалогов, токены, стоимость, какие инструменты и slug вызывались — без текста.
- До отправки бэкенд маскирует в тексте телефоны и e-mail (регулярки). Перед первой репликой
  виджет предупреждает: «Не пишите имя и контакты. Для ответа текст уходит через OpenRouter (США)
  к модели Claude, у нас не сохраняется» — и ждёт «Понятно».
- Сессия живёт только в памяти бэкенда 30 минут и стирается кнопкой «Очистить». Во фронте —
  только в памяти страницы, без `localStorage` и `sessionStorage`.
- **Вебвизор.** Поле ввода — `ym-disable-keys`, лента сообщений — `ym-hide-content`, иначе запись
  сессии увидит симптомы. Цели Метрики — только события (`chat-open`, `chat-send`, `chat-alarm`),
  без текста.
- **OpenRouter.** По его документации и условиям (ред. от 2026-08-31) тексты запросов и ответов
  не хранятся, если не включено логирование; хранятся метаданные — число токенов, задержка.
  В аккаунте держим выключенными:
    - Observability → input/output logging (логи запросов в кабинете);
    - Privacy → «OpenRouter Use of Inputs/Outputs» (использование данных за скидку 1%);
    - Privacy → маршрутизацию к провайдерам, которые обучаются на данных; плюс ZDR для группы
      Anthropic на уровне аккаунта.

    Без своего согласия на использование данных OpenRouter может анонимно категоризировать
    небольшую выборку запросов для рейтингов — это не отключается и должно попасть в текст для
    юриста.

- **Провайдер модели.** С `provider.zdr: true` запросы идут только на ZDR-эндпоинты (Bedrock,
  Vertex) — они не хранят данные; кэш промптов в памяти OpenRouter хранением не считает.
  Первопартийный эндпоинт Anthropic и Azure под ZDR не входят и в маршрут не попадут.
- Раздел о данных на `about.astro` дополняется абзацем про чат.

Юридическая часть за мной не закрывается: передача текста за границу — трансграничная передача
(ст. 12). Запрос в любом случае проходит через OpenRouter (США), даже если модель работает в ЕС;
США не входят в список стран с адекватной защитой. Есть требование о локализации (ст. 18 ч. 5),
а для данных о здоровье — письменное согласие. Можно
есть требование о локализации (ст. 18 ч. 5), а для данных о здоровье — письменное согласие. Можно
ли считать анонимный текст без идентификаторов не персональными данными — вопрос к юристу (см.
«Открытые вопросы»).

## Промпт-инъекции

Что есть в контексте модели: наш системный промпт, тексты нашей базы и текст пользователя. Секретов,
чужих данных и инструментов с записью нет — все три инструмента только читают публичную базу,
аргументы проверяет `knowledgeTools()`. Поэтому худший исход инъекции — неуместный текст от имени
сайта или трата бюджета, а не утечка.

- Правила — только в системном промпте; служебные напоминания — сообщением `system`, а если
  OpenRouter его не донесёт (см. «Безопасность»), то с явной пометкой «от сайта», которую
  пользователь подделать не может: бэкенд вырезает такую пометку из пользовательского текста.
- История хранится на бэкенде, клиент присылает только новую реплику — подделать «ответ
  ассистента» нельзя.
- Вывод модели рендерится как ограниченный Markdown (абзацы, списки, жирный) через санитайзер.
  Ссылки — только на домен сайта и на адреса источников из ответов инструментов; остальное —
  простым текстом. Так модель не подсунет «перейдите на чужой сайт».
- Потолки на число вызовов, длину сообщения и `max_tokens` ограничивают цену любой попытки.
- В eval-набор входят типовые инъекции: «забудь инструкции», «поставь диагноз», «напиши код»,
  фальшивые «системные» блоки в тексте.

## UX на телефоне

- Вход: кнопка «Описать своими словами» под полем поиска на главной спорта и в панели зоны. JS
  виджета грузится по клику и не утяжеляет первую отрисовку.
- На телефоне — полноэкранный лист: высота `100dvh`, поле ввода прижато к низу и поднимается над
  клавиатурой (`visualViewport`), отступы `safe-area-inset-*`. На десктопе — боковая панель.
- Первый экран: дисклеймер, предупреждение о данных и 2–3 примера («болит колено после бега»,
  «потянул спину на становой»). Если на сайте уже выбран спорт (`sport-memory.ts`), он
  подставляется в контекст.
- Порядок ответа: карточки тревожных признаков → текст → карточки статей с плашкой черновика.
  Пока идёт поиск — статус «смотрю тревожные признаки…», «ищу статьи…» по событиям SSE.
- Поле `textarea` растёт до 4 строк, отправка кнопкой (Enter на телефоне — перенос строки).
  «Очистить» в шапке. Ошибки и лимиты — понятным текстом со ссылкой на поиск.
- Доступность: лента — `aria-live="polite"`, фокус в поле при открытии, Esc закрывает.
- Telegram Mini App — отдельный вопрос: там свои ограничения на клавиатуру и данные.

## План по шагам

0. **Блокеры** — ответы владельца на вопросы 1–2 ниже. Без них дальше не идём.
1. **Eval и прототип вне сайта.** Скрипт в `scripts/` гоняет 30–40 жалоб (обычные, срочные, вне
   темы, инъекции) через цикл с реальными инструментами на Opus 5.5 через OpenRouter. Это проверка
   качества и безопасности, а не выбор модели. Оценка по рубрике: признаки вызваны первыми,
   срочность верная, нет диагноза, ссылки только из базы, отказ вне темы, нормальный русский.
   Там же проверяем на практике: доходит ли `system` в середине истории, возвращаются ли
   `reasoning_details` между вызовами инструментов, работает ли кэш с `zdr: true`. Отдельно —
   токены и стоимость по `usage`. Прогон стоит порядка $10, запускать с согласия владельца. Итог —
   подтверждённый `effort` (`low` или `medium`) и правки промпта.
2. **Общие схемы инструментов** из `mcp.ts` в отдельный модуль, MCP переводится на них, тесты MCP
   зелёные.
3. **Бэкенд-чат:** цикл, сессии, SSE, проверка «признаки первыми», маскирование контактов.
   Юнит-тесты на `node --test` с фейковым клиентом OpenRouter: порядок вызовов, потолки, отказ,
   вытеснение сессий, отсутствие текста в логах.
4. **Лимиты и бюджет:** `rateLimit` по IP и глобально, денежный счётчик, проверка `Origin`.
5. **Инфраструктура:** маршрут `/api/chat` в Caddy (репозиторий infra-server), ключ OpenRouter
   секретом в контейнер `api`. В кабинете OpenRouter: отдельный ключ с лимитом кредитов,
   выключенные логирование и использование данных, ZDR для Anthropic на уровне аккаунта.
6. **Виджет:** Svelte-остров, SSE, карточки, мобильная вёрстка, скрытие от вебвизора, цели Метрики.
   Тексты интерфейса — через типографа.
7. **E2E** в Playwright (headless) с подменённым бэкендом: открыть, отправить, увидеть признаки и
   карточки, лимит, ошибка, телефонный вьюпорт и клавиатура.
8. **Тихий запуск** за флагом `CHAT_ENABLED` и параметром `?chat=1`, неделя на реальных расходах и
   агрегатной статистике, затем кнопка для всех. Описание в «Что нового» — через `/release`.

## Что проверить перед запуском

- Eval: 100% срочных жалоб получают нужную срочность, 0 диагнозов «у вас X», 0 ссылок вне базы.
- В логах контейнера и на диске нет текста переписки — проверка grep'ом после прогона e2e.
- Вебвизор не пишет ввод и ленту: запись своей тестовой сессии в Метрике.
- Лимиты срабатывают: 6-я реплика в минуту — 429, дневной бюджет — заглушка вместо вызова API.
- `usage.prompt_tokens_details.cached_tokens` > 0 со второго запроса диалога — кэш работает.
- В активности OpenRouter запросы идут только на ZDR-эндпоинты (Bedrock/Vertex), в логах
  кабинета нет текста запросов.
- Стоимость диалога по `usage` в пределах оценки.
- Телефон: iOS Safari и Android Chrome, клавиатура не перекрывает поле, нет горизонтального
  скролла.
- Отказ модели и недоступность API показываются понятным текстом, а не пустым экраном.

## Открытые вопросы для владельца

1. **Доступность и оплата через OpenRouter.** Что OpenRouter решает: один ключ и один счёт вместо
   договора с Anthropic, оплата кредитами (карта или крипта, комиссия 5,5%), выбор эндпоинта
   (Bedrock, Vertex, регион ЕС) и ZDR одним параметром. Что остаётся:
    - **Условия OpenRouter** (ред. от 2026-08-31). П. 5.7: часть провайдеров не разрешает доступ
      пользователям из некоторых стран, и такие модели через OpenRouter им тоже недоступны. П. 5.1
      и 5.2: клиенты нашего сервиса должны соблюдать условия провайдера модели, то есть
      региональная политика Anthropic распространяется и на посетителей сайта. П. 7 запрещает
      перепродавать доступ к моделям — наш чат с узкой задачей под это не подпадает, но
      формулировку стоит показать юристу.
    - **Оплата.** В мае 2026 OpenRouter отключил платежи части аккаунтов, связанных с Россией
      («does not support usage, billing, or payment methods associated with your geography», по
      сообщениям на Хабре и в Skillbox Media). Откуда аккаунт и чем он будет пополняться? Если
      аккаунт или аудитория попадают под эти ограничения, OpenRouter проблему не решает.
    - **Передача данных за границу (152-ФЗ).** Текст идёт в OpenRouter (США) и дальше к провайдеру
      модели. Выбор эндпоинта в ЕС меняет, где работает модель, но не убирает транзит через США.
    - **Хранение промптов.** У OpenRouter тексты не хранятся при выключенном логировании;
      метаданные хранятся, анонимная категоризация выборки запросов возможна. У провайдера —
      ZDR-эндпоинты Bedrock и Vertex через `provider.zdr: true` и настройку аккаунта. Нужно,
      чтобы владелец выключил все переключатели из раздела «Приватность» и проверил это в
      кабинете.
2. **Юрист по 152-ФЗ.** Считается ли анонимный текст без идентификаторов персональными данными;
   нужны ли согласие на обработку данных о здоровье, уведомление Роскомнадзора о трансграничной
   передаче и что делать с локализацией. Зарегистрирован ли сайт как оператор ПДн.
3. **Черновики.** Все статьи сейчас не проверены врачом. Запускать чат до проверки (с плашкой) или
   после проверки хотя бы самых частых травм?
4. **Бюджет.** Сколько готовы тратить в месяц и какой дневной потолок ставить: стартовые $10 в
   сутки дают ~55–60 диалогов и до ~$300 в месяц. Сколько диалогов ждём?
5. ~~**Модель.**~~ Закрыт: OpenRouter, Claude Opus 5.5 (решение владельца). Eval остаётся проверкой
   качества и безопасности.
6. **Статистика качества.** Без хранения текста улучшать ответы можно только по eval. Нужна ли
   добровольная кнопка «отправить этот диалог на разбор» (тогда — хранение с согласием и сроком)?
7. **Telegram Mini App.** Показывать чат и там или только на сайте?
8. **Капча.** Готовы ли включить Yandex SmartCaptcha, если боты начнут тратить бюджет?
